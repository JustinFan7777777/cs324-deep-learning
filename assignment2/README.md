# CS324 Assignment 2: MLP, CNN and RNN

PyTorch implementations and controlled experiments for CS324 Deep Learning.
The coursework was submitted through Blackboard; this directory is the public
code release. Course PDFs, the submission report/archive, datasets and model
checkpoints are retained locally and are not distributed here.

## Environment and data

Use Python 3.11 and a project-specific environment:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

The listed versions were used for local CPU verification. A fresh-environment
installation has not been tested. Choose a compatible PyTorch build for CUDA;
GPU experiments used the versions listed in `RESULTS.md`.

Run commands from this directory. CIFAR10 is an external download and is
expected under `data/`:

```python
from torchvision.datasets import CIFAR10
CIFAR10('data', train=True, download=True)
CIFAR10('data', train=False, download=True)
```

Toy datasets and palindromes are generated by the supplied code.

## Training and verification

```bash
# Matched NumPy/PyTorch experiments: two datasets, three seeds, two batch sizes.
python 'Part 1/compare_mlp.py'

# Lightweight checks; the CIFAR protocol check needs the downloaded data.
python verify_cifar.py
python 'Part 3/verify_rnn.py'

# Four MLP regularization settings, each at 5,000 optimizer updates.
python cifar_experiments.py train --architecture mlp --variant baseline
python cifar_experiments.py train --architecture mlp --variant dropout
python cifar_experiments.py train --architecture mlp --variant weight_decay
python cifar_experiments.py train --architecture mlp --variant combined

# Required CNN. Full training can be slow on CPU; use --device cuda if available.
python cifar_experiments.py train --architecture cnn --steps 5000 --eval_freq 500

# RNN length study: 15 runs, each with 10,000 updates.
python 'Part 3/run_experiments.py' --lengths 5 9 13 17 21 --seeds 42 43 44 --train_steps 10000 --eval_freq 500 --eval_samples 1000
```

Training produces unique run folders. Use the printed folder for subsequent
evaluation. Freeze architecture/variant selection using validation scores
before evaluating the official test set:

```bash
python cifar_experiments.py test 'PATH_TO_SELECTED_RUN'
python evaluate_cifar_checkpoint.py --help
python 'Part 3/diagnose_rnn.py' 'PATH_TO_RNN_STUDY'
```

`run_cifar_extended.py` runs a fresh 20,000-update MLP/CNN baseline comparison
on CUDA, freezing the study before either test evaluation. `gpu_guard.py`
provides a time limit and optional GPU occupancy protection. Training should
be run only with an appropriate compute budget.

## Reading and rerunning notebooks

The committed notebooks include executed tables, plots and interpretation, so
the results can be read without training. Local machine paths have been removed
from their displayed outputs; numerical values are unchanged.

Raw result folders and weights are intentionally excluded from Git. Therefore,
rerunning all analysis cells in a fresh clone requires regenerating experiments
and updating the notebook's recorded study/run paths to the newly printed paths.
`RUN_STUDY`, `RUN_TRAINING` and `RUN_TEST` default to false to avoid accidental
training or test-set reuse. The root CIFAR notebook also uses downloaded images
for its examples. The original pinned run paths identify the submitted study;
they are not files promised by this public code release.

`audit_artifacts.py` audits the full local submission evidence, including its
selection records and checkpoints. It is not a source-only clone smoke test.
Use the verification scripts above for implementation checks.

## Reproducibility limits

- NumPy and PyTorch toy runs match initialization, dtype, data and batch order.
  Full-batch versus mini-batch results use equal epochs, not equal updates.
- CIFAR10 training uses 45,000/5,000 train/validation images, no augmentation,
  and an untouched official test set for final evaluation. Each image-model
  configuration has one seed; the initial and extended stages use different
  software environments.
- RNN evaluation is isolated from training RNG, but finite palindrome support
  permits repeated sequences and train/evaluation overlap at short lengths.
- RNN exact CPU checkpoint continuation was tested in the same environment.
  CIFAR checkpoints do not implement exact RNG/iterator continuation.
- Fixed seeds do not guarantee bitwise CUDA reproducibility across releases.
